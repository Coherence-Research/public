# Support

Where to ask what, depending on what you need.

## Quick questions, interpretation, implementation chatter

[GitHub Discussions](https://github.com/Coherence-Research/public/discussions). This is the default — when in doubt, open a Discussion.

## Possible errata in a canonical document

Open a GitHub Issue with the `errata` template. Examples: typos, broken links, header field inconsistencies, formatting that violates SC-HDR. These are valuable reports. Please file them.

## Possible specification ambiguity or counterexample

Open a GitHub Issue with the `spec-clarification` template. Examples: a passage where multiple readings are defensible, an apparent inconsistency between sections, or a proposed structural counterexample to an admissibility rule. These are the most valuable reports.

## Contributing improvements to guides or educational material

Read `CONTRIBUTING.md`, then open a PR (or an issue first for substantial changes).

## Reporting an integrity issue

If you find an issue with cryptographic integrity (hash mismatch, Merkle root failure, RCC inconsistency), open an issue with the `errata` template and mark it `integrity` in the description. For coordinated disclosure of anything more sensitive, contact Coherence Research directly via [coherenceresearch.com](https://coherenceresearch.com).

## Hackathon or event questions

Each event has its own directory under `events/`. Read the event README first; it routes you to event-specific support.

## What this repository cannot do for you

- Provide one-on-one specification training (we point to public materials and Discussions instead).
- Implement systems for you (we publish the specification; independent implementation is unrestricted).
- Resolve commercial licensing questions beyond what the LICENSE and stewardship documents already address (see `standards/SC-AS/v1.0/stewardship/`).

---

When in doubt, open a Discussion. We would rather route you to the right place than have you not ask.
